; Tokenization of a word carrying MORE THAN ONE `@` suffix.
;
; These pin SHAPE, never validity: every word below is INVALID CHAT, because a
; word may carry at most one `@` suffix (ruled 2026-08-27, spec/errors/E203.md).
; What is pinned is that the whole run becomes ONE `repeated_form_marker` and
; the word still FORMS, with no ERROR node, so the model can name the defect
; and the word round-trips instead of being silently rewritten.
;
; WHY A HAND-WRITTEN CASE. An E203 example cannot reach the generated corpus:
; membership there is derived from producing ERROR nodes, and this defect is
; lowering-caught precisely because the word parses cleanly. The construct
; corpus is the other half and is for VALID shapes. Without these, the node
; the whole rule rests on had zero `tree-sitter test` coverage.
;
; WHY IT IS WORTH PINNING HERE. This tokenization was wrong twice in one day
; on 2026-08-27: a general pattern swallowed a following language suffix and
; `chatter normalize` deleted it while exiting 0, and the narrowed replacement
; then dropped `word@k@st` to a generic E316. Both were CST mistakes that the
; layers above report only indirectly.
