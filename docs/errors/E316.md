## Unparsable content

> ✅ Active; This check is active in the validator.

**Kind**: Invalidity

**Level**: utterance, tier, header, file

**Status**: ✅ Active

### Description

The parser could not make a construct of some region of the file, and no
more specific rule claimed it. E316 is the generic verdict: it names the
region and says nothing about which rule was broken, which is exactly why
every specific code's spec records where it is reached instead of E316.

### CHAT Rule

None of its own: E316 is reached when the CHAT manual's grammar, as
chatter implements it, is not met and no narrower rule explains how.
The main-tier example set covers a speaker line without a colon, brace
and angle-bracket garbage, and a bullet with its times reversed inside a
postcode. The three `%mor` examples (an item without a separator, and the
two angle-bracket stems below) are E702's since 2026-09-08: a
content-bearing recovery node inside a `%mor` tier is E702 at any depth,
where it was E316 when the node sat below the tier's direct children,
because a context-less walk reported it first. They stay here as the
record of the angle-bracket case, claimed `subsumed_by = 'E702'`.

## Malformed body and ending recovery

> ✅ Active; This check is active in the validator.

**Kind**: Invalidity

**Level**: utterance

**Status**: ✅ Active

### Description

Native ERROR recovery rejects malformed content without inferring narrower syntax from unparsed text. In the nested unclosed-replacement variant, the producer instead inserts a missing right bracket and emits E342, not E316. In the unnested variants, a later postcode bracket can close the replacement; the original punctuation and codes are not thereby unchanged ending payload. The paired source keeps the same prefixes, other turns and dependent notes. The native producer decides which carriers survive; retention is required for genuinely healthy source-owned carriers, not for invented boundaries.

## Malformed inline picture reference

> ✅ Active; This check is active in the validator.

**Kind**: Invalidity

**Level**: tier

**Status**: ✅ Active

### Description

An inline picture reference has a nonempty quoted filename enclosed by NAK
delimiters. Deleting its filename or a closing delimiter must not silently
turn the malformed reference into ordinary comment text.

The valid control parses without diagnostics and roundtrips byte-exactly.
All three deletion variants report E316 during parsing, with no validation
diagnostics and divergent recovered serialization. They become ERROR nodes,
not admitted `inline_pic` tokens, and therefore do not prove that the picture
filename admission guard is redundant.

CHECK (21-Sep-2026), observed on 2026-09-23, reports an error for the missing
closing NAK but not the empty filename or missing closing quote. Its
`check_ParseWords` hidden-token branch checks whether NAK scanning terminated
and reports error 59 if it did not; that branch does not validate the picture
payload on a dependent tier. Chatter retains its stricter structured-picture
syntax. CHECK silence here is not evidence of a usable picture reference.

## Main-tier recovery preserves source-owned neighboring turns

> ✅ Active; This check is active in the validator.

**Kind**: Invalidity

**Level**: utterance

**Status**: ✅ Active

### Description

Incomplete speaker delimiters and malformed word carriers remain invalid.
Deleting the star makes an unprefixed line: the existing E326 rule rejects it,
not E316. This does not witness a Missing/Absent star in a native main tier.
The cases place the fault after Unicode header/content and before an intact
later main tier. Native recovery is inspected separately from the diagnostic
claim: a healthy, source-owned neighboring tier must not disappear from the
model, and fragment diagnostics must name the caller bytes. The bare ampersand
inside a group is a separate recovery boundary: native `other_spoken_event`
recovery absorbs the immediately following turn into an error node. That turn
has no healthy native main-tier carrier; later healthy turns still survive.
Do not infer
Missing/Error/Absent prefix-slot reachability from an invalid source string.

### Examples

#### Example 1

```chat
@UTF8
@Begin
@Languages:	eng
@Participants:	SPK Speaker
@ID:	eng|sample|SPK|||||Speaker|||
@Comment:	Préface café
*SPK:	café ready .
```

## Structured metadata header boundaries

> ✅ Active; This check is active in the validator.

**Kind**: Invalidity

**Level**: header

**Status**: ✅ Active

### Description

`@Types` contains three alphanumeric fields in design, activity, group order,
separated by commas. Optional spaces around those commas do not change the
fields. Truncating the header after design is not a complete Types declaration.
Internal whitespace, punctuation and non-ASCII text do not match those atoms.

The legal controls combine an ordered ISO 639-3 language list, the Types fields
and Unicode free text in `@Situation`. Unicode situation text is not a language
code or a Types field and must retain its authored spelling.
