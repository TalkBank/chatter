# E208: Empty replacement

> ✅ Active; This check is active in the validator.

**Kind**: Invalidity

**Level**: word

**Status**: ✅ Active

## Description

A `[: ]` replacement annotation whose replacement text is empty: the author
wrote the replacement bracket but supplied no replacement word(s). This is a
semantically meaningless replacement: `[: ]` gives the parser/reader nothing
to replace the preceding word with, so it must be rejected.

**Currently unreachable via this exact input**: as the note above records,
`hello [: ] .` is caught earlier, at the parser stage, as E376
(`ReplacementParseError`): tree-sitter's error recovery synthesizes a
placeholder node for the missing replacement word before model-level
validation (which defines E208) ever runs. E208 is not dead code: it exists
for the case where the parser DOES successfully build a `Replacement` value
containing zero words (a different code path than the one this fixture
exercises), which no current fixture demonstrates. This is recorded as a
known, intentional `subsumed_by` relationship, not an authoring gap needing a
fix; see `spec-system-history.md`'s guidance on reading `subsumed_by` claims
as an observation about which stage catches a problem, not a defect.

## Examples

### Example 1

```chat
@UTF8
@Begin
@Languages:	eng
@Participants:	CHI Target_Child
@ID:	eng|corpus|CHI|||||Target_Child|||
*CHI:	hello [: ] .
@End
```

## CHAT Rule

<https://talkbank.org/0info/manuals/CHAT.html#Word> documents `[: replacement]`
as requiring the replacement word(s) to follow the colon; an empty bracket
supplies none and is not valid CHAT.
