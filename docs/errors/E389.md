# E389

> Several rules are reported under this code. Each section below is a
> separate specification with its own status.

## Replacement on a filler

> ✅ Active; This check is active in the validator.

**Kind**: Invalidity

**Level**: utterance

**Status**: ✅ Active

### Description

A replacement `[: text]` is attached to a filler (`&-`), a hesitation
sound that MOR excludes and that has no standard form.

### Examples

#### Example 1

```chat
@UTF8
@Begin
@Languages:	eng
@Participants:	CHI Target_Child
@ID:	eng|corpus|CHI|||||Target_Child|||
*CHI:	&-um [: and] .
@End
```

#### Example 2

```chat
@UTF8
@Begin
@Languages:	eng
@Participants:	CHI Target_Child
@ID:	eng|corpus|CHI|||||Target_Child|||
*CHI:	&-um dog .
@End
```

### CHAT Rule

The manual's Replacement scope `[: text]`: "the item being replaced can
only be a single word" that MOR should analyse under its standard form
(https://talkbank.org/0info/manuals/CHAT.html#Replacement_Scope, https://talkbank.org/0info/manuals/CHAT.html#Replacement_Real). Fillers are marked `&-` (https://talkbank.org/0info/manuals/CHAT.html#Filler_Code) and are excluded from
morphological analysis, so there is nothing for a replacement to feed.

## Filler features do not license replacement

> ✅ Active; This check is active in the validator.

**Kind**: Invalidity

**Level**: word

**Status**: ✅ Active

### Description

Lengthening, a form suffix and an attached overlap boundary preserve the filler category. E389 forbids replacement on that filler, not on the surrounding ordinary word. Each invalid case adds only one replacement annotation; the overlap pair remains balanced.

### Examples

#### Example 1

```chat
@UTF8
@Begin
@Languages:	eng
@Participants:	SPK Speaker
@Options:	CA
@ID:	eng|sample|SPK|||||Speaker|||
*SPK:	&-hmm: [: pause] .
@End
```

### CHAT Rule

These controls extend the existing E389 policy to independently authored word-feature combinations. The paired examples change only the described word or annotation; other source bytes and file options remain fixed.
