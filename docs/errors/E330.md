# E330: Internal CST traversal failure

> ✅ Active; This check is active in the validator.

**Kind**: Invalidity

**Level**: utterance, tier

**Status**: ✅ Active

## Description

The parser's typed walk over the concrete syntax tree met something it could
not decode or dispatch: a node whose text is not valid UTF-8, or a position
where the walk needs a content node and the tree does not have one.

Most of the producers are internal invariants that a correct grammar cannot
violate, and no CHAT text reaches them. Three are different, and are the same
case seen from three dispatchers: when tree-sitter recovers from a malformed
free-text dependent tier by putting an ERROR node where the body belongs, the
reader for that tier reports the ERROR node itself as E316 and then E330 for
the content node it does not have (until 2026-09-08 the E316 came from a walk
the utterance parser ran over every tier before attaching it; the reader owns
both halves now). Which of the three answers depends only on the tier:
`read_tier_body_text` for the text-payload tiers ("Tier is missing content
node", the example above), the shared text-tier body parser for the
bullet-payload tiers such as `%com` ("Missing content in %com tier"), and the
user-defined dispatch for `%x` tiers ("Missing content in user-defined tier
%xfoo").

## Examples

### Example 1

```chat
@UTF8
@Begin
@Languages:	eng
@Participants:	CHI Target_Child
@ID:	eng|corpus|CHI|||||Target_Child|||
*CHI:	<hello [/] .
@End
```

### Example 2

```chat
@UTF8
@Begin
@Languages:	eng
@Participants:	CHI Target_Child
@ID:	eng|corpus|CHI|||||Target_Child|||
*CHI:	<hello world> [/] hello world .
@End
```

### Example 3

```chat
@UTF8
@Begin
@Languages:	eng
@Participants:	CHI Target_Child
@ID:	eng|corpus|CHI|||||Target_Child|||
*CHI:	hello .
%eng:	hello
@End
```

## CHAT Rule

None of its own: E330 names a state of the parse rather than a CHAT
construct. The constructs the reachable example is about are the time bullet
and the dependent tier
(<https://talkbank.org/0info/manuals/CHAT.html#Dependent_Tiers>); the retrace
group in the first two examples is governed by the "Retracing" scoped symbols
(<https://talkbank.org/0info/manuals/CHAT.html#Retracing_Scope>), whose
unclosed form is E316's business.
