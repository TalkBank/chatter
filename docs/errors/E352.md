# E352: MissingQuoteEnd

> ✅ Active (requires `--strict-linkers`); This check is active in the validator, but only when `--strict-linkers` is enabled. A validation run with the default rules does not report it.

**Kind**: Invalidity

**Level**: utterance, file

**Status**: ✅ Active (requires `--strict-linkers`)

## Description

A self-completion linker (`+,`) was used and there IS a prior utterance
from the same speaker, but that prior utterance did not end with a `+/.`
(interruption) terminator, or all prior interruptions have already been
completed. Under the optional strict-linker policy, each interruption can
satisfy only one self-completion.

## Examples

### Example 1

```chat
@UTF8
@Begin
@Languages:	eng
@Participants:	CHI Target_Child
@ID:	eng|test|CHI||male|||Target_Child|||
*CHI:	I want a cookie .
*CHI:	+, actually ice cream .
@End
```

### Example 2

```chat
@UTF8
@Begin
@Languages:	eng
@Participants:	CHI Target_Child, MOT Mother
@ID:	eng|corpus|CHI|||||Target_Child|||
@ID:	eng|corpus|MOT|||||Mother|||
*CHI:	I want +/.
*MOT:	what ?
*CHI:	+, some +/.
*CHI:	+, cookies .
*CHI:	please .
@End
```

### Example 3

```chat

@Begin
```

## CHAT Rule

The `+,` linker pairs with the `+/.` terminator. The prior same-speaker
utterance must end with `+/.` to indicate it was interrupted, and the
`+,` utterance completes it.

A turn carrying both `+,` and `+/.` completes a prior interruption before
introducing its own new interruption. The final paired examples exercise this
order and the refusal to reuse a consumed interruption under the existing
opt-in policy; they do not enable strict-linker checks by default.

CHECK 21-Sep-2026 accepted both lifecycle specimens on 2026-09-23. They
therefore pin Chatter's optional strict policy, not a CHECK rejection.
