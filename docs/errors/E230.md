# E230

> Several rules are reported under this code. Each section below is a
> separate specification with its own status.

## Unbalanced CA delimiter

> ✅ Active; This check is active in the validator.

**Kind**: Invalidity

**Level**: word, utterance

**Status**: ✅ Active

### Description

CA (Conversation Analysis) delimiters are paired prosodic markers (for
example `∆` faster speech, `∇` slower speech, and `°` softer speech) that must
be BALANCED left-to-right across the whole utterance. Every begin-role
occurrence must be matched by a corresponding end-role occurrence somewhere
later in the same utterance. Pairing is computed across the entire
utterance, not per word: `hello∆ world °quiet° end∆` balances even though
the two `∆` occurrences are not adjacent. `hello∆world .` is invalid because
its single `∆` has no matching close anywhere in the utterance.

### Examples

#### Example 1

```chat
@UTF8
@Begin
@Languages:	eng
@Participants:	CHI Target_Child
@ID:	eng|corpus|CHI|||||Target_Child|||
@Comment:	ERROR: Compound delimiter (∆) must be balanced
@Comment:	Invalid: 'hello∆world' - Missing closing ∆
*CHI:	hello∆world .
@End
```

### CHAT Rule

<https://talkbank.org/0info/manuals/CHAT.html#CA_Delimiters> and
<https://talkbank.org/0info/manuals/CHAT.html#CA_Overlaps> document the CA
delimiter set and their paired-marker requirement.

Replacement targets participate in Chatter's utterance-wide balancing, including
inside retraced groups. Thus `<soft [: °quiet]> [/] voice° .` balances, while
deleting its final `°` leaves an unmatched marker and reports E230.

CHECK (21-Sep-2026) gives the opposite results for these exact specimens:
error 117 for the balanced control and no error for the unpaired mutation.
Source inspection identifies duplicate counting, not exclusion. In CHECK's
`check_ParseWords`, the square-bracket token scanner retains the complete
`[: ...]` token. The replacement branch records its closing bracket and resets
the next position to the replacement body, without shortening the current
token. The CA loop therefore scans the target once inside the bracket token
and again when the outer loop visits the replacement words. Both visits toggle
the same `isSofterMatched` state: a single target marker cancels itself, leaving
any following marker unmatched and producing error 117 at end of tier.

The explicit re-entry into replacement text indicates that CHECK processes
replacement contents; it does not establish an intent to exempt their CA
markers. The double toggle is inconsistent with counting each authored marker
once. Chatter deliberately retains its whole-utterance rule rather than
reproducing that traversal defect. Source locations in the inspected
`check.cpp`: token collection 4433–4464, replacement re-entry 4548–4550,
CA scan 4601–4602, softer-state toggle 4644–4648, next position 4916,
and unmatched-marker report 4942–4944.

## Paired CA stretches across word boundaries

> ✅ Active; This check is active in the validator.

**Kind**: Invalidity

**Level**: utterance

**Status**: ✅ Active

### Description

Paired CA prosodic stretches may start and finish on different words. Count
occurrences by delimiter type across the entire utterance, in authored order;
other delimiter types and overlap points do not supply a missing boundary.

### CHAT Rule

Each begin-role CA delimiter needs a later occurrence of the same type in
the same utterance. Its glyph is identical at either boundary: deleting the
first occurrence does not leave a separately spelled close-only token, but
one unpaired occurrence that also reports E230. Different prosodic types
pair independently, including overlapping stretches. This applies the
existing E230 rule without changing replacement-target traversal or CHECK
adjudications.
