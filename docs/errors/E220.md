# E220

> Several rules are reported under this code. Each section below is a
> separate specification with its own status.

## Illegal digits in word content

> ✅ Active; This check is active in the validator.

**Kind**: Invalidity

**Level**: word, utterance

**Status**: ✅ Active

### Description

A word on the main tier contains numeric digits in a language context that does
not permit them. Most natural languages (English, Spanish, French, etc.) do not
allow bare digits in words on the main tier. A small set of languages (Chinese,
Welsh, Vietnamese, Thai, Cantonese, etc.) permit digits as part of tone
notation or numbered homonyms, not as bare numeral words.

Language resolution includes an enclosing `<...> [@s:code]` span. A word's
own marker takes precedence over that span; unmarked words inherit it. Changing
the span must not change the language of an explicitly marked word inside it.

### CHAT Rule

<https://talkbank.org/0info/manuals/CHAT.html>

Languages that allow embedded digits in words: `zho`, `cym`, `vie`, `tha`,
`nan`, `yue`, `min`, `hak`. All other languages flag digits as E220.
Bare numeral words are not covered by this exemption: section 8.8.4 requires
numbers to be written out according to their pronunciation.

### A preceding invalid character does not excuse a digit

The adjacent-fault specimens start with legal `hello`, then the existing
`hello3` violation, followed by `hello’3` and `hello’x3`. Chatter reports parse
E256 and validation E220 for both quote-containing variants. They are invalid
source with recovery output, not roundtrip-valid controls.

CHECK (21-Sep-2026) reports 47 for `hello3`, only 138 for `hello’3`, and both
138 and 47 for `hello’x3`. This positional difference is an execution defect,
not a language-policy exception: `check.cpp::check_CheckWords` increments its
cursor by three when `isBadQuotes` finds the three-byte quote (3197–3199), then
increments again at the loop bottom (3454). The immediately following character
is therefore skipped. Inserting `x` moves the digit beyond that skipped byte
and restores error 47. Chatter deliberately retains both independent faults
without reproducing CHECK's cursor bug.

## Bare numerals are not language-specific tone notation

> ✅ Active; This check is active in the validator.

**Kind**: Invalidity

**Level**: word

**Status**: ✅ Active

### Description

A language exemption for tone digits or numbered homonyms does not permit a
word consisting entirely of ASCII digits. Bare numeral words require E220 even
when a resolved language candidate otherwise allows embedded digits. Omission
notation keeps its separate typed category and is not classified as a numeral.

### Examples

#### Example 1

```chat
@UTF8
@Begin
@Languages:	zho
@Participants:	CHI Target_Child
@ID:	zho|corpus|CHI|||||Target_Child|||
*CHI:	1 10 12 21 101 1001 10000 10001 100000001 100010001 .
@End
```

#### Example 2

```chat
@UTF8
@Begin
@Languages:	zho
@Participants:	CHI Target_Child
@ID:	zho|corpus|CHI|||||Target_Child|||
*CHI:	ma1 本1 .
@End
```

#### Example 3

```chat
@UTF8
@Begin
@Languages:	eng, zho
@Participants:	CHI Target_Child
@ID:	eng|corpus|CHI|||||Target_Child|||
*CHI:	12@s:eng+zho .
@End
```

#### Example 4

```chat
@UTF8
@Begin
@Languages:	eng
@Participants:	CHI Target_Child
@ID:	eng|corpus|CHI|||||Target_Child|||
*CHI:	0word .
@End
```

### CHAT Rule

The [CHAT manual](https://talkbank.org/0info/manuals/CHAT.html), section 8.8.4,
requires numbers to be written out according to their pronunciation. Its
language-code discussion permits tone numbers in Romanized words and homonym
numbers on Chinese characters; those are word components, not bare numerals.

## Currency symbols do not license digits in English lexical words

> ✅ Active; This check is active in the validator.

**Kind**: Invalidity

**Level**: utterance

**Status**: ✅ Active

### Description

English lexical words containing numeric currency amounts still contain illegal
digits. A currency symbol is not an exemption from the lexical digit rule.

### Examples

#### Example 1

```chat
@UTF8
@Begin
@Languages:	eng
@Participants:	CHI Child
@ID:	eng|sample|CHI|||||Child|||
*CHI:	£12 ¥12 ₹12 ₩12 ₽12 €12 12€ 12₹ .
@End
```

### CHAT Rule

Write the spoken words in the main tier. Number expansion is an explicit
generation aid; neither parsing nor validation silently rewrites a transcript.

## English numeric cardinal, ordinal and decade spellings

> ✅ Active; This check is active in the validator.

**Kind**: Invalidity

**Level**: word

**Status**: ✅ Active

### Description

English ordinal and decade suffixes do not license digits in spoken-word
transcription. Write the pronunciation as words. Numeric forms remain invalid
even though their letter suffixes distinguish them from bare numeral tokens.

### Examples

#### Example 1

```chat
@UTF8
@Begin
@Languages:	eng
@Participants:	CHI Target_Child
@ID:	eng|corpus|CHI|||||Target_Child|||
*CHI:	1st 12th 20th 21st 100th 101st 120th 121st 1000th 2000th 1001st 1010th 1100th 1234th 9999th 10s 20s 80s 1900s 1950s 2000s 2010s 1 42 101 1234 2000 10001 20000 1000000 2000000 1000001 2000000000 3000000000000 4000000000000000 5000000000000000000 18446744073709551615 17-year-old 3-star 21-22 21-22-23 90s 1100s 2990s .
@End
```

### CHAT Rule

Transcribe numbers according to their spoken pronunciation. The authored
controls in `corpus/reference/word-features/english-number-spelling.cha` supply
one explicit generation policy, including British-style ordinal conjunctions,
short-scale cardinals without conjunctions, and expanded decade names. The
ordinal controls include thousands with small and hundred-sized remainders.
Generation produces spoken word sequences, without prose commas; it is not
punctuation parity with a general-purpose number-formatting library. The
largest cardinal exercises the generation API's u64 boundary, not an attested
spoken value. These are not production attestations and do not
assert that a context-free generator can recover what a speaker actually said.
Digit-leading compounds likewise require written number words. The generation
controls preserve alphabetic compound tails (`17-year-old`, `3-star`) and
spell each group of an all-numeric dash sequence separately (`21-22`,
`21-22-23`). This is an explicit generation convention, not an inference that a
dash in an original recording was spoken as a range or an omitted word.

## Numeric overflow does not license digit words

> ✅ Active; This check is active in the validator.

**Kind**: Invalidity

**Level**: word

**Status**: ✅ Active

### Description

These authored controls apply the existing E220 digit-word policy to large
numerals. A numeral does not become valid CHAT because its magnitude exceeds
an implementation's numeric range. English ordinal, decade and compound
suffixes do not license its digits either. The overflow decimal value is one beyond
the maximum unsigned 64-bit integer; that is a generation boundary, not a
CHAT validity threshold.

English ordinal composition supports 0–9999. Larger ordinal tokens remain
unchanged, even when their numeric value fits in `u64`: no guessed `th` suffix
or partial expansion is permitted. The authored `9999th`
generation control is in the English number-spelling reference workflow.

Decade composition admits only multiples of ten: shorthand 0–90 or full-year
forms 1100–2990. Other suffix-bearing inputs remain byte-for-byte unchanged;
`21s` and `2001s` do not license guessed phrases such as “twenty-ones” or
“two thousand and ones”. Supported endpoints are paired with authored written
controls. Zero shorthand is tested at the raw-string API boundary because an
initial zero has separate omission semantics in CHAT.

#### Example 1

```chat

@Begin
@Languages:	eng
@Participants:	CHI Target_Child
@ID:	eng|corpus|CHI|||||Target_Child|||
*CHI:	18446744073709551616 18446744073709551616th 18446744073709551616s 18446744073709551616-year-old 10000th 10001st 10002nd 10003rd 10004th 1000001st 18446744073709551615th 1s 21s 99s 100s 1090s 1101s 2001s 2991s 3000s .
@End
```

#### Example 2

*CHI:	18446744073709551616 .

#### Example 3

## Unsupported Spanish number generation preserves digit words

> ✅ Active; This check is active in the validator.

**Kind**: Invalidity

**Level**: word

**Status**: ✅ Active

### Description

Explicit Spanish number generation preserves the complete input when its
bounded cardinal grammar cannot safely express a scale, resolve agreement,
or represent the magnitude. A currency symbol or compound
does not make the numeral valid CHAT or authorize partial generation.

### Examples

#### Example 1

```chat
@UTF8
@Begin
@Languages:	spa
@Participants:	CHI Target_Child
@ID:	spa|corpus|CHI|||||Target_Child|||
*CHI:	1000000 21000 31001 101000 18446744073709551616 1000000€ 21-1000000 21000-year-old .
@End
```
