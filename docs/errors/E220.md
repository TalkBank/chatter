# E220

> Several rules are reported under this code. Each section below is a
> separate specification with its own status.

## Illegal digits in word content

> ✅ Active; This check is active in the validator.

**Kind**: Invalidity

**Level**: word, utterance

**Status**: ✅ Active

### Description

A word on the main tier contains numeric digits in a language context that does
not permit them. Most natural languages (English, Spanish, French, etc.) do not
allow bare digits in words on the main tier. A small set of languages (Chinese,
Welsh, Vietnamese, Thai, Cantonese, etc.) permit digits as part of tone
notation or numbered homonyms, not as bare numeral words.

Language resolution includes an enclosing `<...> [@s:code]` span. A word's
own marker takes precedence over that span; unmarked words inherit it. Changing
the span must not change the language of an explicitly marked word inside it.

### CHAT Rule

<https://talkbank.org/0info/manuals/CHAT.html>

Languages that allow embedded digits in words: `zho`, `cym`, `vie`, `tha`,
`nan`, `yue`, `min`, `hak`. All other languages flag digits as E220.
Bare numeral words are not covered by this exemption: section 8.8.4 requires
numbers to be written out according to their pronunciation.

### A preceding invalid character does not excuse a digit

The adjacent-fault specimens start with legal `hello`, then the existing
`hello3` violation, followed by `hello’3` and `hello’x3`. Chatter reports parse
E256 and validation E220 for both quote-containing variants. They are invalid
source with recovery output, not roundtrip-valid controls.

CHECK (21-Sep-2026) reports 47 for `hello3`, only 138 for `hello’3`, and both
138 and 47 for `hello’x3`. This positional difference is an execution defect,
not a language-policy exception: `check.cpp::check_CheckWords` increments its
cursor by three when `isBadQuotes` finds the three-byte quote (3197–3199), then
increments again at the loop bottom (3454). The immediately following character
is therefore skipped. Inserting `x` moves the digit beyond that skipped byte
and restores error 47. Chatter deliberately retains both independent faults
without reproducing CHECK's cursor bug.

## Bare numerals are not language-specific tone notation

> ✅ Active; This check is active in the validator.

**Kind**: Invalidity

**Level**: word

**Status**: ✅ Active

### Description

A language exemption for tone digits or numbered homonyms does not permit a
word consisting entirely of ASCII digits. Bare numeral words require E220 even
when a resolved language candidate otherwise allows embedded digits. Omission
notation keeps its separate typed category and is not classified as a numeral.

### Examples

#### Example 1

```chat
@UTF8
@Begin
@Languages:	zho
@Participants:	CHI Target_Child
@ID:	zho|corpus|CHI|||||Target_Child|||
*CHI:	1 10 12 21 101 1001 10000 10001 100000001 100010001 .
@End
```

#### Example 2

```chat
@UTF8
@Begin
@Languages:	zho
@Participants:	CHI Target_Child
@ID:	zho|corpus|CHI|||||Target_Child|||
*CHI:	ma1 本1 .
@End
```

#### Example 3

```chat
@UTF8
@Begin
@Languages:	eng, zho
@Participants:	CHI Target_Child
@ID:	eng|corpus|CHI|||||Target_Child|||
*CHI:	12@s:eng+zho .
@End
```

#### Example 4

```chat
@UTF8
@Begin
@Languages:	eng
@Participants:	CHI Target_Child
@ID:	eng|corpus|CHI|||||Target_Child|||
*CHI:	0word .
@End
```

### CHAT Rule

The [CHAT manual](https://talkbank.org/0info/manuals/CHAT.html), section 8.8.4,
requires numbers to be written out according to their pronunciation. Its
language-code discussion permits tone numbers in Romanized words and homonym
numbers on Chinese characters; those are word components, not bare numerals.

## English numeric cardinal, ordinal and decade spellings

> ✅ Active; This check is active in the validator.

**Kind**: Invalidity

**Level**: word

**Status**: ✅ Active

### Description

English ordinal and decade suffixes do not license digits in spoken-word
transcription. Write the pronunciation as words. Numeric forms remain invalid
even though their letter suffixes distinguish them from bare numeral tokens.

### Examples

#### Example 1

```chat
@UTF8
@Begin
@Languages:	eng
@Participants:	CHI Target_Child
@ID:	eng|corpus|CHI|||||Target_Child|||
*CHI:	1st 12th 20th 21st 100th 101st 120th 121st 1000th 2000th 10s 20s 80s 1900s 1950s 2000s 2010s 1 42 101 1234 2000 10001 20000 1000000 2000000 1000001 2000000000 3000000000000 4000000000000000 5000000000000000000 18446744073709551615 .
@End
```

### CHAT Rule

Transcribe numbers according to their spoken pronunciation. The authored
controls in `corpus/reference/word-features/english-number-spelling.cha` supply
one explicit generation policy, including British-style ordinal conjunctions,
short-scale cardinals without conjunctions, and expanded decade names. The
largest cardinal exercises the generation API's u64 boundary, not an attested
spoken value. These are not production attestations and do not
assert that a context-free generator can recover what a speaker actually said.
