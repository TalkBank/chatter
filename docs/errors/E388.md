# E388

> Several rules are reported under this code. Each section below is a
> separate specification with its own status.

## Replacement on a nonword

> ✅ Active; This check is active in the validator.

**Kind**: Invalidity

**Level**: utterance

**Status**: ✅ Active

### Description

A replacement `[: text]` is attached to a nonword (`&~`), which by its
marking is not a word of the language and has no standard form.

### Examples

#### Example 1

```chat
@UTF8
@Begin
@Languages:	eng
@Participants:	CHI Target_Child
@ID:	eng|corpus|CHI|||||Target_Child|||
*CHI:	&~um [: um] .
@End
```

#### Example 2

```chat
@UTF8
@Begin
@Languages:	eng
@Participants:	CHI Target_Child
@ID:	eng|corpus|CHI|||||Target_Child|||
*CHI:	&~um dog .
@End
```

### CHAT Rule

The manual's Replacement scope `[: text]`: "the item being replaced can
only be a single word" that MOR should analyse under its standard form
(https://talkbank.org/0info/manuals/CHAT.html#Replacement_Scope, https://talkbank.org/0info/manuals/CHAT.html#Replacement_Real). The `&~` nonword code is defined beside the filler code in the
manual's special-form section (https://talkbank.org/0info/manuals/CHAT.html#Filler_Code);
the manual has no named anchor for the nonword entry itself.

## Nonword features do not license replacement

> ✅ Active; This check is active in the validator.

**Kind**: Invalidity

**Level**: word

**Status**: ✅ Active

### Description

Form suffixes, repeated lengthening, syllable pauses and paired prosodic markers preserve the nonword category. E388 forbids replacement on the produced nonword regardless of those features. Each invalid case adds only its replacement annotation; the legal control has the same file context and source word.

### Examples

#### Example 1

```chat
@UTF8
@Begin
@Languages:	eng
@Participants:	SPK Speaker
@Options:	CA
@ID:	eng|sample|SPK|||||Speaker|||
*SPK:	&~baba@b [: babble] .
@End
```
