# E553: Header has no content after its colon

> ✅ Active; This check is active in the validator.

**Kind**: Invalidity

**Level**: header

**Status**: ✅ Active

## Description

A colon-bearing header has nothing after its separator: `@Situation:`
followed by its tab and then the end of the line, or only spaces. The header
says it carries content and supplies none, which has no meaning in CHAT. Every
header that can be written this way is refused by one rule; there is no
per-header policy.

The rule covers every colon-bearing header the model carries except
`@Languages`, `@Participants` and `@ID`. Those three declare the transcript's
languages and speakers; their malformed forms, empty ones included, keep their
own codes (E507, E506, E316) and declaration-admission recovery, because a
later rule that needs the declaration must not see it as merely absent.
`@Thumbnail` has no supported model at all, so every `@Thumbnail` line, empty
or not, is refused as unsupported (E525) rather than as empty.

A blank field inside a structured header (`@Media:` followed by a filename, a
type and a trailing comma with nothing after it) is not an empty header: the
header has content, and the field is malformed (E316).

## CHAT Rule

Headers carry the information their name announces
(<https://talkbank.org/0info/manuals/CHAT.html#File_Headers>); an optional
header with no information is omitted, not written empty. The gem headers have
a bare form with no colon
(<https://talkbank.org/0info/manuals/CHAT.html#Bg_Header>).
