# E600: Tier alignment skipped due to parse errors

> ✅ Active; This check is active in the validator.

**Kind**: Invalidity

**Level**: utterance, tier

**Status**: ✅ Active

## Description

E600 reports an unavailable or skipped alignment for retained parsed tiers.
For example, a stray character before a `%mor` prefix taints the utterance even
when the MOR tier itself parses, so main-to-MOR alignment cannot be trusted.

A wholly rejected dependent tier is different: its explicit unparsed variant
retains the source and model validation rejects it as E316. It does not create
a parsed alignment merely to emit E600. The non-integer GRA example above now
records that rejection; the doubled-prefix control demonstrates E600 itself.

## Examples

### Example 1

```chat
@UTF8
@Begin
@Languages:	eng
@Participants:	CHI Child
@ID:	eng|corpus|CHI|||||Child|||
*CHI:	hello world .
%mor:	int|hello n|world .
%gra:	abc|0|ROOT 2|0|ROOT
@End
```

### Example 2

```chat
@UTF8
@Begin
@Languages:	eng
@Participants:	CHI Target_Child
@ID:	eng|corpus|CHI|||||Target_Child|||
*CHI:	hello .
%%mor:	co|hello .
@End
```

## CHAT Rule

Dependent tiers and the utterance context must parse cleanly before their
alignment can be trusted. Repair the primary error before using alignment.
