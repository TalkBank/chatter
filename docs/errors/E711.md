# E711

> Several rules are reported under this code. Each section below is a
> separate specification with its own status.

## Mor empty content

> ✅ Active; This check is active in the validator.

**Kind**: Invalidity

**Level**: tier

**Status**: ✅ Active

### Description

A %mor word has an empty stem, POS category, prefix, suffix, or FEATURE
VALUE. Every morphosyntax item on the %mor tier must have a non-empty POS
category and a non-empty stem at minimum, and every feature it carries must
have a value.

The feature value was missing from this sentence until 2026-09-08, and it is
the only one of the five that any CHAT input reaches: an empty stem and an
empty POS are both caught structurally before the model is built, which is
what the old `status_note` correctly observed before drawing the wrong
conclusion from it. `n|dog-Num=` is a word with a non-empty POS and a
non-empty stem, and `MorFeature::is_empty` reports its keyed feature as empty
because the value after `=` is.

### Examples

#### Example 1

```chat
@UTF8
@Begin
@Languages:	eng
@Participants:	CHI Target_Child
@ID:	eng|test|CHI||female|||Target_Child|||
*CHI:	want cookie .
%mor:	v| n|cookie .
@End
```

#### Example 2

```chat
@UTF8
@Begin
@Languages:	eng
@Participants:	CHI Target_Child
@ID:	eng|test|CHI||female|||Target_Child|||
*CHI:	want cookie .
%mor:	|want n|cookie .
@End
```

#### Example 3

```chat
@UTF8
@Begin
@Languages:	eng
@Participants:	CHI Target_Child
@ID:	eng|corpus|CHI|||||Target_Child|||
*CHI:	dog .
%mor:	n|dog-Num= .
@End
```

### CHAT Rule

The %mor tier format is `POS|stem` with optional prefix, suffix, and fusion
markers. Neither POS nor stem may be empty. See the CHAT manual:
https://talkbank.org/0info/manuals/CHAT.pdf

## Empty features on main and post-clitic morphology words

> ✅ Active; This check is active in the validator.

**Kind**: Invalidity

**Level**: tier

**Status**: ✅ Active

### Description

A post-clitic is a morphological word with its own features, not an unchecked
suffix of its host. Both the main word and every post-clitic require nonempty
feature values. Flat and keyed features retain their distinct written forms.

### Examples

#### Example 1

```chat
@UTF8
@Begin
@Languages:	eng
@Participants:	CHI Target_Child
@ID:	eng|corpus|CHI|||||Target_Child|||
*CHI:	it's .
%mor:	pron|it-Nom~aux|be-Pres .
@End
```

#### Example 2

```chat
@UTF8
@Begin
@Languages:	eng
@Participants:	CHI Target_Child
@ID:	eng|corpus|CHI|||||Target_Child|||
*CHI:	it's .
%mor:	pron|it-Case=Nom~aux|be-Tense=Pres .
@End
```

#### Example 3

```chat
@UTF8
@Begin
@Languages:	eng
@Participants:	CHI Target_Child
@ID:	eng|corpus|CHI|||||Target_Child|||
*CHI:	it's .

@End
```

#### Example 4

*CHI:	it's .

#### Example 5

```chat
@UTF8
@Begin
@Languages:	eng
@Participants:	CHI Target_Child
@ID:	eng|corpus|CHI|||||Target_Child|||
*CHI:	it's .
%mor:	pron|it-Case=~aux|be-Tense= .
@End
```

### CHAT Rule

Every morphological feature must have content, including features carried by
post-clitics. A keyed feature requires a value after its equals sign. This is
the existing E711 rule applied independently to each morphological word.
