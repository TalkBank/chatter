## Scoped annotation parse error

> ✅ Active; This check is active in the validator.

**Kind**: Invalidity

**Level**: word, utterance

**Status**: ✅ Active

### Description

A scoped annotation (a square-bracketed code) cannot be parsed where it
stands: malformed bracket sequences, unmatched closing annotation
brackets, or a replacement glued to its word with no space before the `[`.
An explicit code-switch annotation whose optional colon/code group recovers
as `ERROR` is also refused here. It is not the bare shortcut `[@s]`.

Malformed bracket runs remain invalid, but their rejection does not establish
a three-level nesting limit. The first example is reported as generic E316;
no maximum-depth rule is inferred from its recovery text.

### CHAT Rule

The manual's Multiple Repetitions section retires `[x N]` as of September
2022. Write each spoken repetition explicitly, with `[/]` marking the
repeated material: `hey [x 2]` becomes `hey [/] hey`. Merely moving a
count after a word does not make the legacy notation valid.

Scoped symbols are square-bracketed and preceded by a space
(https://talkbank.org/0info/manuals/CHAT.html#Scoped_Symbols); CLAN CHECK error 161 states the space requirement.

The CHAT manual's retracing discussion places pauses and fillers between
the initial speech and its repetition after the retracing marker, not before
it (<https://talkbank.org/0info/manuals/CHAT.html>). The paired pause examples
preserve this ordering boundary (CHECK 159). E375 describes the fragment
recovery historically reached by repetition and correction. These cases now
use E316, like reformulation; none is a dedicated pause-ordering diagnostic.

## Unmatched delimiters across body positions

> ✅ Active; This check is active in the validator.

**Kind**: Invalidity

**Level**: utterance

**Status**: ✅ Active

### Description

Closing square brackets without an opening annotation are not valid spoken material. These specimens retain an unparsed ERROR region, not a typed scoped annotation whose decoder could justify E375. They preserve the established E375 unmatched-delimiter subsumption policy: E316 owns rejection. These paired variants exercise the existing scoped-annotation boundary at distinct body positions, including a nested group.

## Retired repetition counts without a terminator

> ✅ Active; This check is active in the validator.

**Kind**: Invalidity

**Level**: utterance

**Status**: ✅ Active

### Description

Missing utterance structure does not make retired repetition-count notation
valid. These malformed combinations complement the terminated `[x N]` cases
in `E375.md`. The control writes the spoken repetitions explicitly.

### Examples

@UTF8
@Begin

@Participants:	CHI Target_Child
@ID:	eng|corpus|CHI|||||Target_Child|||
*CHI:	hey [/] hey .
@End
```

@Languages:	eng
@Participants:	CHI Target_Child
@ID:	eng|corpus|CHI|||||Target_Child|||

```

#### Example 3

```chat
@UTF8
@Begin
@Languages:	eng
@Participants:	CHI Target_Child
@ID:	eng|corpus|CHI|||||Target_Child|||
*CHI:	[x 2]
@End
```

### CHAT Rule

The CHAT manual retired `[x N]` in September 2022 in favor of explicit
repetition with `[/]`; see its
[Disfluency Transcription section](https://talkbank.org/0info/manuals/CHAT.html).
An utterance also requires a terminator. These examples deliberately retain
both faults to exercise recovery, not to redefine either rule.
