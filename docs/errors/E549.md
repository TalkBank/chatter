# E549: Duplicate speaker declaration

> ✅ Active; This check is active in the validator.

**Kind**: Invalidity

**Level**: header

**Status**: ✅ Active

## Description

The same speaker code is declared more than once in the `@Participants` header
or has more than one `@ID` header.
Each participant must be declared exactly once; a repeated speaker code is a
declaration error.

## Examples

### Example 1

```chat
@UTF8
@Begin
@Languages:	eng
@Participants:	CHI Target_Child, CHI Target_Child
@ID:	eng|corpus|CHI|||||Target_Child|||
*CHI:	hello .
@End
```

### Example 2

```chat
@UTF8
@Begin
@Languages:	eng
@Participants:	CHI Target_Child
@ID:	eng|corpus|CHI|||||Target_Child|||
@ID:	eng|corpus|CHI|||||Target_Child|||
*CHI:	hello world .
@End
```

### Example 3

```chat
@UTF8
@Begin
@Languages:	eng
@Participants:	CHI Target_Child
@ID:	eng|corpus|CHI|||||Target_Child|||
*CHI:	hello world .
@End
```

### Example 4

```chat
@UTF8
@Begin
@Languages:	eng
@Participants:	CHI Target_Child, MOT Mother
@ID:	eng|corpus|CHI|||||Target_Child|||
@ID:	eng|corpus|MOT|||||Mother|||
*CHI:	hello world .
*MOT:	hello .
@End
```

## CHAT Rule

Each participant is declared exactly once in `@Participants`. Declaring the same
speaker code twice is an error. Each speaker also has exactly one `@ID` header;
an identical repeated header is still a duplicate, not an idempotent update.

This closes a chatter/CLAN-CHECK parity gap: CLAN CHECK reports error 13
("Duplicate speaker declaration") for this construct, which chatter previously
accepted.
