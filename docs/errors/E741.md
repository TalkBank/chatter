# E741: Phoaln actual side does not reproduce the pho word

> ✅ Active; This check is active in the validator.

**Kind**: Invalidity

**Level**: tier

**Status**: ✅ Active

## Description

Concatenating the actual (right) sides of `%xphoaln`, skipping ∅, must
reproduce the `%pho` word. The comparison is segment-level: stress markers (`\u{02C8}`, `\u{02CC}`)
and syllable-boundary notation (Phon's `^`, IPA's `.`) in either string are
ignored, and the linking tie (`\u{203F}`, which joins two symbols into one
segment or marks the absence of a break) is ignored in the `%pho` word,
since the alignment pairs carry bare segments while the source word may
carry suprasegmental, boundary and linking notation. A pair side that
carries a tie is not a bare segment and is compared as written.

## Examples

### Example 1

```chat
@UTF8
@Begin
@Languages:	eng
@Participants:	CHI Target_Child
@ID:	eng|corpus|CHI|||||Target_Child|||
*CHI:	cat .
%mod:	kæ
%pho:	kæt
%xphoaln:	k↔k,æ↔æ
@Comment:	ERROR: the %xphoaln actual side concatenates to 'kæ', which does not match %pho 'kæt'
@End
```

### Example 2

```chat
@UTF8
@Begin
@Languages:	deu

*CHI:	Pferd .

%xphoaln:	p↔p,f↔f,ɛ↔ɛ,ɐ↔ɐ,t↔t
@End
```
