## Description

A postcode `[+ ...]` after the terminator carries no code: nothing, or only
whitespace, between `[+ ` and `]`.

## Expected Behavior

`tree_parsing/postcode/mod.rs` strips the delimiters and trims; an empty
result is reported as E363 over the postcode. When the grammar's token does
not match at all (`[+ ]`, exactly one space), the line is recovered and
reported as E316 instead. A postcode with a code is not reported; chatter
does not judge which codes are meaningful, only that one is present.

**Trigger**: See examples above

## CHAT Rule

The CHAT manual's "Utterance level error coding (post-codes)" section (18.2
in the current manual, no named anchor; `#_Toc208734963` in the 2026-09-03
build) defines a postcode as `[+ code]` placed after the terminator.

## Notes

- The parser's other E363 route is a UTF-8 decoding failure inside the
  postcode node, which valid CHAT cannot produce.
