## Description

An `@ID` line does not have the shape the manual prescribes: ten
pipe-separated fields, each of which may be empty.

## Expected Behavior

An `@ID` that tree-sitter cannot structure retains an E316 diagnostic at the
actual recovery span. Its text is not reparsed to manufacture an ID header or
a field-specific E505 diagnosis. An `@ID` with all ten fields parses,
whatever its fields hold; the fields are then judged one by one (E510,
E511, E515, E532, E546). An `@ID` short by exactly one field parses with a
MISSING placeholder and is reported as E342 rather than E505. The canonical
claims above distinguish those source behaviors from model-only boundaries.

**Trigger**: See examples above

## CHAT Rule

The manual's `@ID` header: `@ID: language|corpus|code|age|sex|group|SES|role|education|custom|`,
one per participant, fields left empty when unknown (https://talkbank.org/0info/manuals/CHAT.html#ID_Header).

## Notes

- A speaker declared in `@ID` but not in `@Participants` is E523; a
  participant with no `@ID` at all is reported through the join, not here.
