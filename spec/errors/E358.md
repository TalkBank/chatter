**Last updated:** 2026-09-03 18:06 EDT

## Description

A long-feature begin marker `&{l=LABEL` is never closed by an `&}l=LABEL`
with the same label anywhere later in the file.

## Expected Behavior

Validation walks every utterance of the file in order, keeping a stack of
open long-feature labels (`validation/cross_utterance/scoped_markers.rs`);
a begin still open at the end of the file is reported as E358 at the begin
marker. A begin closed by a same-label end, in the same utterance or a later
one, is not reported.

**Trigger**: See examples above

## CHAT Rule

The CHAT manual's "Long Events" section (9.10.5 in the current manual, which
has no named anchor for it; `#_Toc208734929` in the 2026-09-03 build) defines
`&{l=LABEL` and `&}l=LABEL` as the begin and end of a long event, and the
matching nonvocal pair `&{n=LABEL` / `&}n=LABEL`; the labels of a pair are the
same, and the pair may span several utterances of one file.

## Notes

- Long features and nonvocals (E367/E368) share one algorithm, selected by
  family; underline markers (E356/E357) do not yet, for the reason the
  module's own documentation gives.
- The end marker's label must match: `&{l=singing` closed by `&}l=laughing`
  leaves the begin unmatched (E358) and reports the end as E359.
