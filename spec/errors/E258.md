## Description

Two comma separator items occur consecutively in document order with no
intervening content. CHAT uses one comma for a syntactic break; the two-comma
sequence is not a stronger version of that separator.

## Expected Behavior

The parser builds both separator items and validation reports E258 at the
second comma. A single comma between words does not trigger E258.

Opaque dependent-tier text is not a sequence of main-tier separators. The
malformed `%gra` example is legal only with respect to E258: its invalid
grammar-tier syntax must still be rejected, without inventing main-tier
punctuation semantics for a recovery fragment. CHECK 107/156 likewise gate
their literal comma checks on a main speaker tier.

**Trigger**: See example above

## CHAT Rule

The CHAT manual's “Comma” section permits a comma after a word to mark a
syntactic break and requires commas to be space-delimited:
<https://talkbank.org/0info/manuals/CHAT.html#Comma>. CLAN CHECK 107/156
separately rejects repeated literal commas; if `,,` was intended as the
Conversation Analysis tag marker, write the distinct U+201E character (`„`).

## Notes

- CHECK-parity fixtures ground E258 against both the double-comma and
  three-or-more-comma diagnostics.
- Validation traverses typed utterance content in document order, including
  nested groups; it does not search raw source text for `,,`.
