## Description

A main tier line has no speaker code between `*` and `:`, so nothing says
which participant produced the utterance.

## Expected Behavior

The line is recovered as a main tier with an empty speaker code and reported
as E301. E304 is the diagnostic the typed prefix conversion issues when the
parse tree carries a main tier with a MISSING or zero-width speaker node
(`main_tier/structure/convert/prefix.rs`); with the current grammar that
node is never produced for raw CHAT, so the code is unreachable from a file
and E301 is the observable verdict. Both codes say the same thing about the
line.

**Trigger**: See example above

## CHAT Rule

The CHAT manual's "Main Line" section requires an asterisk, a speaker ID,
a colon and a tab at the start of every main tier:
<https://talkbank.org/0info/manuals/CHAT.html#Main_Line>; the speaker ID is
one of the codes declared in `@Participants`
(<https://talkbank.org/0info/manuals/CHAT.html#Speaker_ID>).

## Notes

- This is a permanent, intentional subsumption unless the grammar changes to
  produce a MISSING speaker node for `*:`; if it does, the example's claim
  flips to `violates` and this note goes.
- `MissingSpeaker` is also the code the prefix conversion reports when the
  leading `*` itself is absent from a main-tier node, which is a parse-tree
  shape and not a CHAT construct.
