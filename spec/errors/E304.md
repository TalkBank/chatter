## Description

A main tier line has no speaker code between `*` and `:`, so nothing says
which participant produced the utterance.

## Expected Behavior

The line is rejected with E316. E304 is the diagnostic the typed prefix conversion issues when the
parse tree carries a main tier with a MISSING or zero-width speaker node
(`main_tier/structure/convert/prefix.rs`). The retained example does not
produce that node; E316 is its observable verdict. The generated slot API
still permits recovery states, so this example does not prove E304 unreachable
for every CHAT file. No extra speaker-specific diagnostic is required to
establish that this source is invalid.

**Trigger**: See example above

## CHAT Rule

The CHAT manual's "Main Line" section requires an asterisk, a speaker ID,
a colon and a tab at the start of every main tier:
<https://talkbank.org/0info/manuals/CHAT.html#Main_Line>; the speaker ID is
one of the codes declared in `@Participants`
(<https://talkbank.org/0info/manuals/CHAT.html#Speaker_ID>).

## Notes

- Preserve this example's E316 subsumption unless new observations justify
  adjudicating a changed result. Do not remove recovery on the strength of
  this example or invent a node state to claim CHAT coverage.
- Required-position admission excludes Error and Absent states for the
  prefix fields before conversion. The prefix converter does not report
  E304 for an absent leading `*`; lexical MISSING star and tab placeholders
  retain their separate recovery policy.
