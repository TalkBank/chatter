**Last updated:** 2026-10-19 10:05 EDT

## Description

An utterance contains material no rule of the grammar or of the recovery
classifiers recognizes, here a stray closing brace. Braces in CHAT belong to
long-feature and nonvocal scopes (`&{l=...` ... `&}l=...`), and a bare `}`
belongs to nothing.

## Expected Behavior

For a stray brace inside the main tier, whole-file parsing recovers the
main-tier content and the classifier reports the unparsable region as E316
(unparsable content). E324 is the utterance parser's last-resort verdict for
an ERROR node at an utterance child position that matched no named rule: a
stray character before a dependent tier prefix (`%%mor:`, `@%mor:`) reaches
it from a whole file, the tier itself still parsing as its own element and
the utterance's parse health tainted. Well-formed content parses without
either code.

**Trigger**: See example above

## CHAT Rule

The manual has no rule for a stray brace as such; it defines what braces
mean in the "Scoped Symbols" section
(<https://talkbank.org/0info/manuals/CHAT.html#Scoped_Symbols>), and
anything outside those forms is not CHAT.

## Notes

- The registry summary "unrecognized error in utterance content" is
  accurate: this is a catch-all with no rule of its own, and the spec cannot
  give it a boundary beyond "the grammar did not accept it". The third
  example demonstrates it as `violates` from a whole file.
