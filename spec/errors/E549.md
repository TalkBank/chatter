## Description

The same speaker code is declared more than once in the `@Participants` header
or has more than one `@ID` header.
Each participant must be declared exactly once; a repeated speaker code is a
declaration error.

## Expected Behavior

- **Parser**: Should succeed, the syntax is valid
- **Validator**: Reports E549 for a repeated participant declaration or a
  repeated speaker identity among the `@ID` headers. Distinct speakers do not
  conflict merely because they share a language or other demographic fields.

## CHAT Rule

Each participant is declared exactly once in `@Participants`. Declaring the same
speaker code twice is an error. Each speaker also has exactly one `@ID` header;
an identical repeated header is still a duplicate, not an idempotent update.

This closes a chatter/CLAN-CHECK parity gap: CLAN CHECK reports error 13
("Duplicate speaker declaration") for this construct, which chatter previously
accepted.
