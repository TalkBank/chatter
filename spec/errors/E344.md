## Description

An utterance ends with the quotation-precedes terminator `+".`, which says
"the quotation came BEFORE this", but the nearest earlier turn by the same
speaker was not marked as the quotation with the `+"` linker, or no such
turn exists. Intervening turns by other speakers do not sever the connection.

## Expected Behavior

With quotation validation enabled, `check_quotation_precedes`
(`validation/cross_utterance/quotation_precedes.rs`) looks back through the
nearest preceding turn by the same speaker and requires it to carry `+"`.
An intervening turn by another speaker is skipped; ordinary speech by the
same speaker severs the quotation. An older quotation cannot satisfy the rule
past that ordinary turn. With the flag off (the default), E344 is not reported.

**Trigger**: See examples above

## CHAT Rule

The CHAT manual's "Quotation Precedes" terminator `+".` and the "Quoted
Utterance" linker `+"` are defined as a pair:
<https://talkbank.org/0info/manuals/CHAT.html#QuotationPrecedes_Terminator>,
<https://talkbank.org/0info/manuals/CHAT.html#QuotedUtterance_Linker>, under
"Utterance Linkers"
(<https://talkbank.org/0info/manuals/CHAT.html#Utterance_Linkers>).

## Notes

- The registry variant is the historical `InvalidContentAnnotationNesting`;
  the earlier spec example (nested angle brackets) was about that name, not
  about what the code reports, and could only ever produce E316. The code has
  reported the quotation rule since the cross-utterance validators were
  written.
- Whether this rule becomes a warning, becomes context-sensitive, or is
  dropped is the open decision recorded in
  `validation/cross_utterance/mod.rs`; the spec records the rule as
  implemented.
- CHECK 21-Sep-2026 accepted both intervening-speaker examples on 2026-09-23.
  These pin Chatter's existing optional strict policy, not a CHECK rejection;
  default Chatter validation does not enable E344.
