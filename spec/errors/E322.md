## Description

This diagnostic represents a main-tier prefix with a zero-width (MISSING)
colon node. A missing colon in source does not necessarily produce that node:
the retained deletion examples instead produce ERROR recovery and E316.

## Expected Behavior

E322 is reserved for an actual MISSING colon node. The authored example
instead reaches E316, as its claim states; it does not witness that recovery
state. The single-colon deletion in `E316_speaker_colon.md` also reaches E316
despite retaining the tab. Neither example justifies marking E322 implemented.

The prefix converter calls the internal reporter only from the generated
slot's `Missing` arm; it does not reclassify recovery by checking a raw
node's byte width. The reporter receives a source-bound
`SourceField<ColonNode>`, not a distinct Missing-only parameter type.
The current call site preserves the distinction, but the reporter's
signature alone does not exclude a present colon.

## Notes

- Tree-sitter error recovery synthesizes a MISSING colon placeholder
  at `child.start_byte() == child.end_byte()`.
- **Status note**: The example above triggers E316 (generic parse error)
  rather than E322. Tree-sitter handles the missing colon through a different
  error recovery path. Triggering E322 requires tree-sitter to produce a
  zero-width MISSING colon node specifically.
