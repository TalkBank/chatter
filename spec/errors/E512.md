notes = '''
A single word in `@Participants` is read as a CODE with no role, so the
participants parser reports E513, never E512: there is no way to write an
entry with a role and no code, because the first word is the code.

@Begin
@Languages:	eng
@Participants:	Target_Child
*CHI:	hello .
@End
'''

## Description

A `@Participants` entry with no speaker code.

## Expected Behavior

Unreachable from raw CHAT, and MEASURED so on 2026-09-08 rather than only
reasoned: five shapes were put through `chatter validate` looking for a
code-less entry, a doubled comma, a spaced empty entry between commas, a
leading comma, a trailing comma, and a trailing comma with spaces. They
produced E316, E320, E342, E522, E523, E550 and E758, and never E512. Where
the speaker is absent tree-sitter inserts a MISSING node and
`check_not_missing` reports E342 before this rule's arm is reached. The
registry status is `unreachable_from_chat` as of that date; it had said
`implemented` while this section said the opposite.

An entry's first word is its code, so the
missing part of a one-word entry is always the role (E513). E512's
producers (`participants.rs`, the model's entry constructor) fire only for
an entry the parser built with an empty code, which the grammar does not
produce. A `CODE Role` entry is not reported.

**Trigger**: See example above

## CHAT Rule

Each `@Participants` entry is `XXX Name Role` (https://talkbank.org/0info/manuals/CHAT.html#Participants_Header).
