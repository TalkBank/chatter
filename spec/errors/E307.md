## Description

A speaker code must be ASCII. It is structurally unusable if it contains the
colon reserved to terminate a main-tier speaker prefix or because it exceeds
CHAT's seven-character maximum.

Non-ASCII codes are rejected consistently in typed validation and main-tier
recovery as E307. E522 remains about participant/ID relationships, not character
syntax. Existing supported ASCII lowercase and punctuation forms remain legal.

## Expected Behavior

Validation reports E307 for the malformed code wherever the typed speaker code
is checked, including participant headers and main tiers. A supported code of
at most seven characters does not trigger E307.

**Trigger**: See example above

## CHAT Rule

The CHAT manual's `@Participants` “Speaker ID” section says speaker IDs are
usually three letters and that CLAN accepts IDs up to seven characters:
<https://talkbank.org/0info/manuals/CHAT.html#Speaker_ID>. The main-line grammar
uses a colon after the ID, so a colon cannot also be part of the ID:
<https://talkbank.org/0info/manuals/CHAT.html#Main_Line>.

## Notes

- E307 is about the code's own structure. E308 is the separate relational
  error for a structurally usable main-tier code absent from `@Participants`.
- Chatter deliberately accepts legacy and corpus-specific codes beyond the
  manual's usual three-uppercase-letter form, while retaining the delimiter
  and length invariants needed for unambiguous CHAT.
