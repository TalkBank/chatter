## Description

A nonempty `@Time Duration` value must match one of the three time patterns
in Chatter's duration-header policy:

```
@Time Duration:	@t<hh:mm-hh:mm>  @t<hh:mm:ss-hh:mm:ss>  @t<hh:mm:ss>
```

That is, the value is exactly one of:

- `HH:MM-HH:MM`: two times separated by a hyphen, hours+minutes only
- `HH:MM:SS-HH:MM:SS`: two times separated by a hyphen, hours+minutes+seconds
- `HH:MM:SS`: single time, hours+minutes+seconds

Nothing else: no semicolon separator, no comma-joined multi-segment
value, no millisecond suffix, no standalone `MM:SS` two-component form.
Two-component range endpoints are hours and minutes, unlike the minutes and
seconds of a two-component `@Time Start` or `%tim` value. Parsing must retain
that distinction before clock bounds are assessed. CHECK is comparison evidence,
not authority to override these typed meanings.

## Expected Behavior

- **Parser**: preserves the duration field, including an empty optional value.
- **Validator**: reports E540 at the header span when a nonempty value
  does not match exactly one of:
  - `^\d+:\d+-\d+:\d+$`: `HH:MM-HH:MM`
  - `^\d+:\d+:\d+-\d+:\d+:\d+$`: `HH:MM:SS-HH:MM:SS`
  - `^\d+:\d+:\d+$`: `HH:MM:SS`

Component widths are not fixed (`\d+` rather than `\d{2}`) because
real corpora use `1:30` as well as `01:30`; depfile.cut's `hh` /
`mm` / `ss` slots admit any digit count. The rejection is about
**shape and clock range**, not component padding. Hours must be in 0–23;
minutes and seconds must be in 0–59. These bounds apply independently to
both endpoints of a range. A structurally parsed time can still violate
the bounds; it need not become an unsupported value to be invalid.
An empty value retains the existing omission policy: no E540, no invented
duration in CHAT output. The empty-value and suffix controls live in
`E540_numeric_boundaries.md`.

## CHAT Rule

CLAN `depfile.cut`:

```
@Time Duration:	@t<hh:mm-hh:mm> @t<hh:mm:ss-hh:mm:ss> @t<hh:mm:ss>
```

CHAT manual: <https://talkbank.org/0info/manuals/CHAT.html#Time_Duration_Header>

## Notes

- CHECK boundary observation (21-Sep-2026 build): it rejects `99:99:99`
  and `00:00:00-23:60:00` with code 35, but accepts
  `24:00:00-23:59:59`. Chatter's existing clock-range rule rejects that
  last value because its start hour is 24. This is a recorded boundary
  difference, not evidence that CHECK enforces every Chatter bound.
- Authoritative source: `clan-info/lib/depfile.cut:33`.
- Severity upgraded from `Warning` to `Error` to mirror CLAN's
  rejection.
- Roundtrip fidelity is preserved: unsupported text and structured values
  with out-of-range components both retain their original spelling.
