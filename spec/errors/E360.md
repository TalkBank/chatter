**Last updated:** 2026-09-03 18:32 EDT

## Description

A media bullet the parser can recognize as a bullet but not accept: the
registered meaning covers malformed timestamp content and the deprecated
skip form `start_end-`.

## Expected Behavior

Largely unreachable from raw CHAT. The grammar pre-validates bullet
content as digits, so non-numeric content is E316 before E360's
producers run; the deprecated skip form is likewise rejected by the
grammar as E316. A `0_0` bullet parses and passes this rule (its
relation is E362's business, and E362 does not fire for it either, see
Notes).

**Trigger**: See examples above

## CHAT Rule

Bullets are `\u0015start_end\u0015`, two millisecond counts
(https://talkbank.org/0info/manuals/CHAT.html#TimeAlignment_Scope); the skip variant with a trailing dash is no
longer supported.

## Notes

- Until 2026-09-03 this code had two spec files; both status notes, kept:
  - skip form: Unreachable via tree-sitter parser. The grammar's strict NAK-delimited media-bullet rule rejects the deprecated `start_end-` skip variant (dash before closing NAK) before Rust validation runs, producing E316 instead of E360. The Rust check (`InvalidMediaBullet`) only fires for bullets that parsed as `media_bullet` nodes but fail the structural check; the skip-dash form never parses as a media bullet.
  - invalid content: Partially unreachable via tree-sitter parser. E360 is emitted in three code paths: (1) `parse_media_bullet` for legacy token-style bullets (dead code for structured grammar), (2) `parse_internal_bullet` for content-area bullets where `parse_bullet_node_timestamps` returns None, and (3) `parse_inline_bullet` for dependent-tier bullets where `0_0` IS checked. However, the grammar's `bullet` rule (`bullet_timestamp: /[0-9]+/`) pre-validates numeric content, so `parse_bullet_node_timestamps` always succeeds for grammar-accepted bullets. The `0_0` check in `parse_media_bullet` and `parse_inline_bullet` fires, but `utterance_end.rs` and `internal_bullet.rs` skip this check, `0_0` bullets pass through to the model where E362 (start >= end) fires instead.
- `0_0` validates clean today although E362 is a strict `start < end` rule;
  either E362 is not reached for utterance-final bullets of zero length or
  the model does not build one. Recorded as a WP4 question.
