## Description

A media bullet the parser recognizes but cannot accept, including timestamp
overflow and an all-zero inline dependent-tier timestamp pair. Malformed text
that never becomes a structured bullet can instead produce syntax diagnostics.

## Expected Behavior

Numeric lexical acceptance does not prove timestamps fit in `u64`; the overflow
example exercises that distinction. The inline dependent-tier decoder also
rejects a NAK-delimited `0_0` pair with E360. The first two historical examples
lack NAK delimiters and therefore make no claim about structured bullet
acceptance. In particular, the second example cannot establish utterance-final
zero-duration behavior or whether E362 is emitted for a real zero-duration bullet.

**Trigger**: See examples above

## CHAT Rule

Bullets are `\u0015start_end\u0015`, two millisecond counts
(https://talkbank.org/0info/manuals/CHAT.html#TimeAlignment_Scope); the skip variant with a trailing dash is no
longer supported.

## Notes

- Earlier notes inferred structured-bullet behavior from undelimited input and
  incorrectly treated lexical digit acceptance as numeric range validation.
  The explicit overflow and inline all-zero examples supersede those claims.
- The inline decoder's admitted timestamp value excludes only the all-zero
  pair; it is not itself a proof of increasing time or whole-file validity.
- The explicitly delimited skip-bullet examples exercise structured-bullet
  recovery both inside speech and at tier end. Removing only the trailing
  dash produces a clean modern bullet in either position. Current CHECK
  (21-Sep-2026 build) does not reject that dash; Chatter's existing rule is
  stricter, and this observation does not reinstate the legacy form.
