## Description

A `@Bg` (begin gem) header has no matching `@Eg` (end gem) later in the
file: for a labelled gem, no `@Eg` with the same label; for an unlabelled
one, no bare `@Eg`.

## Expected Behavior

`validation/header/structure.rs::check_gem_balance` counts open scopes per
label over the file's headers in order; every scope still open at the end
is reported as E526, with the count and label. The diagnostic is anchored
at the file start, since the scope it names was opened earlier and never
closed. A gem closed by a same-label `@Eg` is not reported.

**Trigger**: See examples above

## CHAT Rule

The CHAT manual's `@Bg` and `@Eg` headers
(<https://talkbank.org/0info/manuals/CHAT.html#Bg_Header>,
<https://talkbank.org/0info/manuals/CHAT.html#Eg_Header>): each `@Bg` must
have a matching `@Eg`, and when the colon form is used the text after `@Eg:`
must exactly match the corresponding `@Bg:`. One pair may be nested inside
another, but "double embedding is not allowed". The lazy form `@G`
(<https://talkbank.org/0info/manuals/CHAT.html#G_Header>) marks gems that
neither nest nor overlap, each running to the next `@G`.

## Notes

- A label mismatch (`@Bg: Story` ... `@Eg: Game`) reports E528 on the
  `@Eg` and ALSO leaves the `@Bg` unmatched (E526) and the `@Eg` unmatched
  (E527); the three codes describe one mistake from three sides.
