## Description

An `@Media` header contains a status value that is not one of the recognized values. The file parses successfully but the unsupported status is stored as `Unsupported(String)` and flagged during validation.

## Expected Behavior

- **Parser**: Should succeed, syntax is valid
- **Validator**: Should report E536, unsupported @Media status 'badstatus'

## CHAT Rule

The `@Media` header accepts status values: `unlinked`, `missing`, `notrans`. Any other status value is flagged as unsupported.

Reference: <https://talkbank.org/0info/manuals/CHAT.html#Media_Header>

### CHECK boundary

CHECK 21-Sep-2026 reports no status error for the empty-status mutation in
E342's examples. Its `check.cpp` media-header loop (5553–5624) skips commas
and whitespace before searching for another token and stops at end of input.
It therefore never validates an empty trailing field. Chatter retains the
distinction between an omitted optional field and an explicitly introduced
but empty unsupported value. This is a deliberate stricter syntax policy,
not a claim that CHECK recognizes an empty status keyword. The CHECK fixture
run also reports its independent transcript/media basename mismatch (157).

## Notes

This is an error-level invalidity diagnostic. Unsupported media status values
are preserved in the model for roundtrip fidelity; preservation is not
acceptance. E342's media-status deletion pair demonstrates the distinction
between omitting the entire optional status group and retaining an empty
unsupported status after its comma. The latter reports E536, not E342.
