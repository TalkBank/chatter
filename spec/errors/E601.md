**Last updated:** 2026-09-03 18:22 EDT

## Description

A dependent tier line has a valid name and delimiter but content the
tier's own grammar cannot make anything of, here a `%mor` line of nothing
but separators.

## Expected Behavior

The dependent-tier parsers (`tier_parsers/dependent_tier.rs` and the
per-tier dispatch) report E601 over the tier when its content parses to
no items at all or to a shape the tier cannot hold. A tier with
well-formed content is not reported; a tier with a malformed HEADER (no
colon, no tab) is E602.

**Trigger**: See examples above

## CHAT Rule

Dependent tiers begin with `%`, a three-letter code, a colon and a tab,
followed by content in the format that tier defines
(https://talkbank.org/0info/manuals/CHAT.html#Dependent_Tiers); `%mor` items are `pos|stem` (https://talkbank.org/0info/manuals/CHAT.html#Morphological_Tier,
https://talkbank.org/0info/manuals/CHAT.html#MOR_Format).

## Notes

- Which tier names exist is not this rule's business: a user-defined
  `%x...` tier accepts free text, and an unknown three-letter tier name is
  currently accepted as well (probed 2026-09-03), which is a WP4 question.
