## Description

A structurally usable speaker code on a main tier is absent from the file's
`@Participants` declaration. This is a cross-reference failure, not a claim
that the code's spelling is intrinsically invalid.

## Expected Behavior

When `@Participants` declares at least one speaker, validation reports E308 on
a main-tier code that is neither declared there nor the special unidentified
speaker code `0`. A main-tier code present in `@Participants` does not trigger
E308.

**Trigger**: See examples above

## CHAT Rule

The CHAT manual says `@Participants` is obligatory and lists all speakers in
the file:
<https://talkbank.org/0info/manuals/CHAT.html#Participants_Header>. Main-tier
speaker IDs identify which listed participant produced each utterance:
<https://talkbank.org/0info/manuals/CHAT.html#Utterance_Speaker_Code>.

## Notes

- The first example's `CH-I` is not being rejected merely for containing a
  hyphen; it triggers E308 because the file declares `CHI`, not `CH-I`.
- E307 is the separate rule for a speaker code that is structurally invalid.
- Chatter also emits W108 with expected participant codes for this condition;
  E308 remains the invalidity diagnostic.
