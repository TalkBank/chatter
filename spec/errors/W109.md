## Description

The `@Media` header's filename and the transcript's own filename are the
same name under Unicode canonical equivalence (comparing NFC forms), but
at least one side is not itself already spelled in NFC: a decomposed
accented letter (base letter plus a combining mark, e.g. "u" + combining
diaeresis U+0308) instead of the single precomposed codepoint (e.g. "ü",
U+00FC). Both spellings render identically and refer to the same media, so
this is not the real filename mismatch that E531 reports; it is a
canonicalization notice.

This warning also applies when both names have identical decomposed bytes.
Use `chatter fix --code W109 --apply <file>` to rewrite only the `@Media`
filename token to its standard NFC spelling. The command preserves all other
bytes and never renames files. If the stored filename also needs normalization,
its warning remains until the file is renamed separately with a tool that
preserves NFC; Finder is not suitable for that repair. Remote URLs are exempt
and are never normalized by this fix.

TalkBank filenames and `@Media` names are canonically UTF-8 NFC. A
non-canonical spelling usually enters a corpus from an editor, OS, or
transfer tool that defaults to NFD (or another decomposed form) rather
than from a deliberate choice, so this warning exists to surface it for a
corrections pass rather than let it accumulate silently or, worse, be
mistaken for and "fixed" as a real E531 filename mismatch.

## Expected Behavior

`check_media_filename_match`
(`crates/talkbank-model/src/model/file/chat_file/validate/checks.rs`)
compares the `@Media` filename and the transcript filename under Unicode
NFC first. If the NFC forms differ, it reports E531 as before. If the NFC
forms match but either original is not NFC, it reports W109 instead,
naming which side (the `@Media` name, the file name, or both) is not
already NFC.

**Trigger conditions**: `@Media` filename and the CHAT file's own name are
canonically equal (same string once both are normalized to NFC) but are
not both already in NFC. Identical decomposed names warn about both sides.
On-disk validation uses the spelling stored in the directory, not a spelling
typed at the command line. Resolution failure must not disable named checks.

## CHAT Rule

The CHAT manual does not address Unicode normalization directly; this is a
TalkBank corpus-hygiene rule layered on top of the `@Media`
filename-matching convention (see E531), adopted so that "the same
filename" has one unambiguous byte representation across the corpus
instead of two visually indistinguishable ones.

## Notes

- This does not fire when both sides are already NFC and identical (the
  common case), nor when the NFC forms genuinely differ (that stays E531).
- CLI-level coverage recreating both the NFC/NFD pairing and the
  all-NFC-already case lives in
  `crates/chatter/tests/integration/media_filename_match_tests.rs`,
  alongside E531's own CLI tests, because (like E531) this check depends on
  the caller-provided file name, not just the transcript's own content.
