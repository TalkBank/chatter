## Description

Chatter cannot admit a header name into its supported model. This includes
invented names and the grammar-recognized but unsupported `@Thumbnail` form.
Free text belongs in `@Comment` or `@Situation`, not under an invented name.
Recognizing a name in the grammar does not by itself implement its semantics.

## Expected Behavior

An invented name is retained as an unknown header and model validation reports
E525 over its line. `@Thumbnail` takes the grammar's explicit typed alternative,
but lowering reports E525 and refuses a modeled header. Both routes must prevent
strict admission of the document; their stage and wording need not be identical.
The known `@Comment` control accepts its free-text payload. Header names in the
manual are not a guarantee of current Chatter support.

**Trigger**: See examples above

## CHAT Rule

See the CHAT manual's "File Headers" chapter for format background:
<https://talkbank.org/0info/manuals/CHAT.html#File_Headers>. Chatter reports
unsupported names explicitly instead of inventing a header meaning. Legacy
`@Page` syntax is rejected by the grammar as E316, as the subsumption control
records; it does not additionally require E525.

## Notes

- Until 2026-09-03 this spec carried four gem examples (nested `@Bg`, `@G`
  inside a scope, unmatched `@Bg`, unmatched `@Eg`) subsumed by E529, E530,
  E526 and E527; they belong to those codes, where each has its own
  example, and were removed here.
- A header with a known name but a malformed value is a different code
  (E505 for `@ID`, the `Empty...Header` family for empty values).
