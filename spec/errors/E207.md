## Description

A `[...]` scoped annotation whose marker CLAN/chatter does not recognize as
one of the defined scoped-annotation types (e.g. `[: text]` replacement,
`[/]` retracing, `[* code]` error coding, and the rest of the closed set the
grammar defines). In the authored `[@ ...]` examples, the current grammar
produces an ERROR node, and the parser reports E207. These examples do not
produce a structured `ContentAnnotation::Unknown` for validation. Their
recovered serialization diverges from the input; recovery is not acceptance.

`hello [@ xyz] world .` is invalid because `@` is not a defined scoped
annotation marker (word-level `@` suffixes like `@b`/`@c` are a completely
different construct, a word-suffix rather than a bracketed annotation; see E203).

A bare `&` is also incomplete: it supplies neither a defined ampersand-prefixed
word form nor its content. The paired filler examples distinguish a complete
filler from the result of truncating it to that marker alone.

## Expected Behavior

The scoped-comment host-deletion pair preserves the annotation bytes while
removing its preceding word. The control is diagnostic-free and byte-exact;
the mutation reports parse-stage E375 and E342 and diverges on serialization.
Its recovery is nested inside a retained main tier, so it does not exercise
the separate whole-line E207 fallback for a leading inline annotation.

The unknown-marker examples, including the marker following a replacement
(`dog [: cat] [@ animal] .`), report E207 during parsing and no validation
diagnostics. The corresponding explanation-marker controls parse without
diagnostics and roundtrip byte-exactly. The claim requires E207 presence;
the per-stage observation snapshot does not assert diagnostic multiplicity.

The model also has a structured `ContentAnnotation::Unknown` representation
with its own diagnostic construction. That model boundary is distinct from
these source-parsed recovery examples: they are not evidence that its
validation or serialization paths have been exercised. Do not remove those
paths merely because these CHAT fixtures cannot reach them.

The parser reports E207 for a recovery node consisting of a bare ampersand.
The grouped filler mutation reaches this path. In the ungrouped example,
recovery absorbs the preceding word as well, and E316 reports the larger
region; the explicit subsumption preserves that specificity gap for future work.

## CHAT Rule

<https://talkbank.org/0info/manuals/CHAT.html#Scoped_Symbols> lists the closed
set of defined scoped-annotation markers. A marker outside that set is not
valid CHAT; chatter reports it as E207 rather than silently accepting it or
downgrading the whole utterance to an unparsable-content error (E321/E316).

## Notes

- Do not confuse unknown scoped markers with E203 (invalid `@` word-suffix
  form markers): the former concern a `[...]` annotation; E203 concerns
  a word's own `@`-suffix.
- A malformed bracket (e.g. an unterminated `[`) is a different failure mode.
  Unknown-marker and bare-ampersand recovery have separate parser classifiers;
  neither classifier establishes that a structured unknown annotation exists.
