**Last updated:** 2026-09-08 22:00 EDT

## Description

A `%mor` tier whose content does not parse as morphological items
(`pos|stem` with optional affixes, one per main-tier word).

## Expected Behavior

There is no E382 today: an empty POS or another malformed item leaves the tier unparsable, which is E702 from
recovery (the `%mor` verdict for a content-bearing recovery node at any
depth) with E600 (generic tier error) from validation. A well-formed tier
is not reported. These examples do not justify a second verdict over E702;
the registry's `not_implemented` status is not an instruction to duplicate
the existing rejection.

**Trigger**: See examples above

## CHAT Rule

The `%mor` tier's item format is defined in the manual's dependent-tier
chapter (https://talkbank.org/0info/manuals/CHAT.html#Dependent_Tiers) and in the MOR documentation; a `%mor` line
has one item per word, `pos|stem` with affix codes.

## Notes

- Any future distinct rule needs an independently justified invalid construct,
  not just a desire to emit E382. Registry retirement remains separate from
  the already-covered malformed-item behavior.
