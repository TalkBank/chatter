## Description

Unparsable content within a `%mor` item. Missing separators, missing stems,
extra pipes and malformed compound structure are distinct examples; the
diagnostic must not claim that every such item lacks a pipe.

The paired `catfish` examples keep the speech fixed and contrast a complete
single lemma with an extra pipe (CHECK 79) and malformed compound structure
(CHECK 87). A recovery fragment beginning with `|fish` inside an existing
item is not an independently authored empty-POS item: E760 must not replace
the morphology error merely because the CST split the invalid item there.

## Expected Behavior

E702 IS emitted, and until 2026-09-08 this paragraph said it was not. The
producer is an ERROR-node classifier in
`tree_parsing/parser_helpers/error_analysis/dependent_tier.rs`, and its
condition is narrower than the code's name suggests: the tier is `%mor`, and
the recovery ERROR node has non-empty content. Nothing about a pipe.

Both examples reach it. Until 2026-09-08 example 1 did not, and this
paragraph explained that by the grammar ("fails the tier grammar early");
the real reason was the reporter: the utterance parser walked every tier's
children before attaching it and reported the ERROR without the tier's name,
so a recovery node below the tier's direct children was classified without
the `%mor` context and fell to E316, while a direct child got E702 from the
typed dispatch. One reporter now walks the whole tier in the tier's words,
so the condition above holds at any depth.

The earlier claim was one input generalised to a rule, and the registry
recorded the same mistake as `status = 'not_implemented'`, which is the status
that excuses a code from the demonstration gate.

**Trigger**: See example above

## CHAT Rule

`%mor` items are `pos|stem` with optional prefix, suffix and translation
fields (https://talkbank.org/0info/manuals/CHAT.html#MOR_Format).

## Notes

E702 is implemented. E382 and E361 have separate registry statuses and are
not evidence that this diagnostic is absent.
