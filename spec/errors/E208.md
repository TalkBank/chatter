## Description

A `[: ]` replacement annotation whose replacement text is empty: the author
wrote the replacement bracket but supplied no replacement word(s). This is a
semantically meaningless replacement: `[: ]` gives the parser/reader nothing
to replace the preceding word with, so it must be rejected.

**Unreachable under the canonical parser, and not only via this input**: as
the note above records, `hello [: ] .` is caught earlier, at the parser stage,
as E376 (`ReplacementParseError`) plus E342 for the MISSING slot tree-sitter's
error recovery inserts, before model-level validation (which defines E208)
ever runs. The stronger fact, which this page previously got wrong, is that no
other input reaches the rule either: there is no tree-sitter code path that
successfully builds a zero-word `Replacement`. Three things forbid it, in
order. The grammar admits a replacement only as `repeat1(standalone_word)`, so
the empty form is outside the language. `parse_replacement` ends with
`if words.is_empty() { ParseOutcome::rejected() }`, so it refuses to construct
the value rather than handing an empty one downstream. Its only caller
degrades a rejected replacement to a plain `Word`, dropping the annotation.
The `is_empty()` arm of `impl Validate for ReplacementWords` therefore has no
reachable input on that backend. This is recorded as a known, intentional
`subsumed_by` relationship, not an authoring gap needing a fix; see
`spec-system-history.md`'s guidance on reading `subsumed_by` claims as an
observation about which stage catches a problem, not a defect.

## Expected Behavior

The parser rejects this input and reports parse-stage errors
(`ReplacementParseError` / E376, and `MissingRequiredElement` / E342 for the
recovery slot) at the location of the empty brackets, because the grammar has
no zero-word `Replacement` to build from `[: ]` and the replacement parser
declines to invent one.

## CHAT Rule

<https://talkbank.org/0info/manuals/CHAT.html#Word> documents `[: replacement]`
as requiring the replacement word(s) to follow the colon; an empty bracket
supplies none and is not valid CHAT.

## Notes

- **The rule is not dead code: it fires under the other backend.** The re2c
  parser lexes `[: ]` as a replacement whose content is a single space (its
  content class admits one), splits that content on whitespace, and calls
  `Replacement::new` on the resulting empty vector with no non-empty guard of
  the kind the canonical parser has. So `chatter validate --parser re2c` on
  this very example reports E208, and the disagreement is already recorded as
  `("E208.md", Conflicting)` in the backend-parity baseline. The observation
  snapshot runs the tree-sitter parser only, so it cannot see that, which is
  why this code is implemented, reachable, and still demonstrated by no
  example. Reading its registry status as wrong would be the wrong conclusion.
- **A second emit site carries this code for an unrelated condition.** The
  tree-sitter main-tier recovery classifier returns `EmptyReplacement` for a
  recovery node whose text begins with the vocative marker `‡` (U+2021), under
  the message "Unrecognized freecode". A stray vocative marker is not an empty
  replacement, so that is a code misassignment, not a second reading of this
  rule. No example is written for it here on purpose: an example that fired it
  would put E208 in the snapshot while demonstrating something this page does
  not describe, which is worse than an honest gap.
- If a future parser change makes `[: ]` actually construct a
  zero-word `Replacement` at the model layer instead of failing to parse, this
  spec's `claim` should change from `subsumed_by = 'E376'` to `violates`, and
  the observation snapshot diff would flag exactly that transition as a
  review event. The type-level alternative closes the door from the other
  side: make `ReplacementWords` non-empty by construction, in the mould of
  `AnnotatedContentAnnotations::new`, which would delete this rule's model
  emit site outright and force the re2c backend to name the malformed bracket
  instead of an empty replacement.
