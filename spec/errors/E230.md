## Description

CA (Conversation Analysis) delimiters are paired prosodic markers (for
example `∆` faster speech, `∇` slower speech, and `°` softer speech) that must
be BALANCED left-to-right across the whole utterance. Every begin-role
occurrence must be matched by a corresponding end-role occurrence somewhere
later in the same utterance. Pairing is computed across the entire
utterance, not per word: `hello∆ world °quiet° end∆` balances even though
the two `∆` occurrences are not adjacent. `hello∆world .` is invalid because
its single `∆` has no matching close anywhere in the utterance.

## Expected Behavior

The parser successfully parses the file (an unpaired delimiter is not a
syntax error: the character is a legal word-content symbol on its own);
validation then reports E230 for each begin-role delimiter left unpaired
after left-to-right role assignment across the utterance.

## CHAT Rule

<https://talkbank.org/0info/manuals/CHAT.html#CA_Delimiters> and
<https://talkbank.org/0info/manuals/CHAT.html#CA_Overlaps> document the CA
delimiter set and their paired-marker requirement.

## Notes

- Implementation: `crates/talkbank-model/src/validation/utterance/ca_delimiter.rs`
  assigns `Begin`/`End` roles by left-to-right pairing for every type in the
  generated `CADelimiterType` registry, then reports E230 for an occurrence
  left open. These markers use the same glyph at both boundaries, so an
  unmatched occurrence starts a region; there is no separately spelled
  close-only token.
- This spec's single example only exercises `∆`. Legal paired examples and
  violating examples across the other registered delimiter types would
  strengthen coverage of the rule's full closed-set scope.
