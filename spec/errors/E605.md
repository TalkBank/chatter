## Description

An utterance contains a dependent tier with a label that is not a standard CHAT tier name and does not follow the `%x` user-defined tier naming convention. The file parses successfully but the tier is stored as `DependentTier::Unsupported` and flagged during validation.

## Expected Behavior

- **Parser**: Should succeed, syntax is valid
- **Validator**: Should report E605, unsupported dependent tier '%foo'

## CHAT Rule

Dependent tiers must use a supported standard tier or the `%x` user-defined
namespace (for example `%xfoo`, `%xtra`, `%xcoref`). The grammar and typed tier
catalog own the supported inventory; a second list here must not advertise
retired tiers as supported.

The paired examples retain the same speech and opaque payload while changing
only the tier label. Labels longer than the legacy CLAN reader boundary remain
legal in the user-defined namespace. This reflects the 21-Sep-2026 reader
change exempting `%x` labels from that short-name limit, not removal of every
CLAN input-size limit. A long non-`x` label does not acquire that namespace.

Reference: <https://talkbank.org/0info/manuals/CHAT.html#Dependent_Tiers>

## Notes

This is an error-level diagnostic. Unsupported dependent tiers are preserved
in the model for roundtrip fidelity. `DependentTier::Unsupported` distinguishes
unknown tiers from intentional user-defined tiers. Their complete labels and
payloads must survive parsing and writing; a length-boundary test must not
pass merely because a prefix was truncated into a different supported name.
