## Description

A semicolon separator on a main tier is not valid modern CHAT, including
inside groups or retraced material. The parser retains a typed separator so
validation can report its exact position without losing the original spelling.
Parsing and lossless serialization do not certify validity.

## Expected Behavior

The comma control validates. Replacing the comma with a semicolon produces
E769 at that separator. Nested and retraced semicolons receive the same rule.
Header age delimiters and opaque dependent-tier text are outside this rule.

## CHAT Rule

The current HTML CHAT manual's [Separators section](https://talkbank.org/0info/manuals/CHAT.html#Semicolon)
disallows semicolons on main tiers: chaining utterances this way causes
incorrect syntactic analyses. Split utterances appropriately; a CA light
final drop uses `↘`, not `;`. CHECK 21-Sep-2026 reports 48 for the simple
semicolon example. Older documentation described limited historical use;
that does not establish validity under the current rule.
