## Description

An utterance begins with the quoted-utterance linker `+"`, which marks it as
quoted speech, but nothing around it says whose quotation it is: no earlier
same-speaker utterance ended with `+"/.` (quotation follows) and no later
one ends with `+".` (quotation precedes).

## Expected Behavior

With quotation validation enabled, `check_quoted_linker`
(`validation/cross_utterance/quoted_linker.rs`) accepts the linker when
either pattern holds and reports E346 on the utterance otherwise. With the
flag off (the default), neither example reports anything.
CA's optional ordinary terminators do not replace the explicit quotation
opener or closer. The CA controls distinguish an admitted omission from a
missing quotation relationship under the same opt-in policy.

**Trigger**: See examples above

## CHAT Rule

The "Quoted Utterance" linker `+"` continues a quotation announced by the
`+"/.` terminator or closed by the `+".` terminator:
<https://talkbank.org/0info/manuals/CHAT.html#QuotedUtterance_Linker>,
<https://talkbank.org/0info/manuals/CHAT.html#QuotationFollows_Terminator>,
<https://talkbank.org/0info/manuals/CHAT.html#QuotationPrecedes_Terminator>.

## Notes

- The registry variant is the historical `UnmatchedContentAnnotationEnd`;
  the earlier spec example (a stray `>`) was about that name and could only
  ever produce E316. What the code reports is the quotation rule above.
- Same open decision as E344 (warning, context-sensitive, or dropped),
  recorded in `validation/cross_utterance/mod.rs`.
