## Description

A `@Bg:` opens a gem whose label is already open: the same label nested
inside itself.

## Expected Behavior

`check_gem_balance` keeps a count of open scopes per label and reports E529
at a `@Bg` whose label already has an open scope. Nesting one labelled pair
inside another with a DIFFERENT label is allowed and not reported.

**Trigger**: See examples above

## CHAT Rule

The CHAT manual's `@Bg` and `@Eg` headers
(<https://talkbank.org/0info/manuals/CHAT.html#Bg_Header>,
<https://talkbank.org/0info/manuals/CHAT.html#Eg_Header>): each `@Bg` must
have a matching `@Eg`, and when the colon form is used the text after `@Eg:`
must exactly match the corresponding `@Bg:`. One pair may be nested inside
another, but "double embedding is not allowed". The lazy form `@G`
(<https://talkbank.org/0info/manuals/CHAT.html#G_Header>) marks gems that
neither nest nor overlap, each running to the next `@G`.

## Notes

- The manual also forbids "double embedding" (a third level of nesting)
  regardless of labels; chatter does not check depth today, so a
  three-deep nesting under three labels validates clean. That is a WP4 gap,
  recorded here rather than pretended.
- The original example wrote `@Bg:test` with no tab after the colon; the
  example now uses the tab the manual requires, so it demonstrates only
  this rule.
