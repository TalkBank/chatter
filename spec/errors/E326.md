## Description

A line was classified as an unexpected type during file structure parsing.
This covers two sub-cases:

1. A line matched by tree-sitter's `unsupported_line` rule, a
   catch-all for content that doesn't conform to any recognized CHAT line
   shape (header, utterance, or dependent tier).
2. A child of a LINE node whose kind is completely unknown to the
   Rust parser, a grammar/parser mismatch.

## Expected Behavior

The parser reports E326 with error severity for the bare text line.
Tree-sitter matches it as `unsupported_line` since it doesn't start with
any recognized prefix.

Recovery skips the unsupported line and preserves subsequent well-formed
utterances. Each unsupported line carries its own source span, including its
line break. A tab-indented continuation belongs to the preceding tier and
does not trigger E326. Error severity makes recovery explicit without treating
the skipped content as valid CHAT.

## Notes

- The `corpus/reference/constructs/unsupported.cha` file exercises this
  via an unsupported line, as well as `unsupported_header` and
  `unsupported_dependent_tier`.
- Both unsupported lines and unknown LINE child kinds use error severity.
  Earlier prose described the unsupported-line case as a warning; that did
  not match the canonical parser's behavior.
