**Status:** Current
**Last updated:** 2026-09-03 17:20 EDT

## Description

The file contains a control character that CHAT does not use. The only
control characters a CHAT file may hold are TAB (the delimiter between a tier
name and its content), the line endings LF and CR, U+0015 (the delimiter
around a time bullet), and the two CA underline markers, which are the pairs
U+0002 U+0001 (begin) and U+0002 U+0002 (end). Anything else (a lone U+0001,
CLAN's italics pairs U+0002 U+0003 and U+0002 U+0004, a form feed, DEL, a C1
control) is not text and cannot be transcription.

## Expected Behavior

The rule is lexical and is decided over the whole input before any parse
(`talkbank-parser`'s `lexical` module), so every forbidden character is
reported as E315 at its own offset, wherever it sits: in a word, in a `%com`
line, in a header value. Inside a word the character also breaks the word's
parse, so E316 accompanies it there. Bullets, tabs and underline pairs are
never reported; an attribute lead byte with any other code is reported
character by character.

**Trigger**: See examples above

## CHAT Rule

The CHAT manual states no rule about control characters beyond requiring the
file to be UTF-8 text
(<https://talkbank.org/0info/manuals/CHAT.html#UTF8_Header>); the rule here
is chatter's own, and matches CLAN CHECK's error 86 ("Re-enter using
Unicode"). There is no manual section to cite for it.

## Notes

- Until 2026-09-03 this code was decided by two ERROR-node classifiers, so a
  control character reached E315 only when the grammar failed around it: in a
  word it surfaced as E316, and in free-text tiers and header values it was
  silently accepted. Both classifiers are deleted; the lexical scan replaced
  them.
- A word containing a control character is additionally reported by the
  model's word-structure validation, which reads the parsed word, not the
  source.
