+++
code = 'E340'
name = 'UnknownBaseContent'
+++

## Description

Main tier content could not be classified as any known word or construct
type. This fires when the generated traversal cannot place the child of a
`base_content_item` CST node in the one position the rule has (the slot's
`Unexpected` state), which is a grammar/parser mismatch: the grammar and
the traversal generated from it disagree about what may stand there.

## Notes

- This error indicates a grammar/parser mismatch, not a CHAT input error.
- It cannot be triggered by any CHAT input with the current grammar; it
  would only fire if the grammar added a new `base_content_item` variant
  without updating the Rust parser. That is what `Status:
  unreachable_from_chat` says, and this spec asserted it in prose while
  claiming `implemented` until 2026-08-20.
- No example is possible with the current grammar, and no test constructs
  the condition either, because constructing it means fabricating a node the
  grammar cannot produce. Between 2026-08-20 and 2026-09-09 a hand-written
  mirror of the alternatives (`BaseContentKind::from_node_kind`) made the
  trigger a total function with two tests, which pinned the mirror against
  itself and could not notice the grammar gaining an alternative.
- The trigger is now the generated traversal's own classification:
  `parse_base_content` in
  `crates/talkbank-parser/src/parser/tree_parsing/main_tier/content/base/mod.rs`
  matches the generated `BaseContentItemChoice` exhaustively, so an
  alternative the grammar gains is a compile error rather than this
  diagnostic, and E340 is reported only for a node the classifier could not
  place in the position (`NodeSlot::Unexpected`). What keeps that
  classification current is `generated_traversal_is_current`; what measures
  it against the repository is
  `cargo run -p talkbank-parser-tests --example slot_state_census`, which on
  2026-09-09 found no position of any rule in `Unexpected` over the spec
  examples and the reference corpus.
