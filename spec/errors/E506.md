## Description

The `@Participants` header is present but declares nobody.

## Expected Behavior

The model reports E506 when the entry list it is given is empty. An empty
or space-only header value reaches it through tree-sitter's MISSING speaker
(E342 from the parser, the entry dropped; a space-only value adds E758);
the parser has no empty-header producer of its own since 2026-10-19, when
its arm for an `Absent` first entry (a state the typed walk cannot produce)
became an internal producer-fault report. The parser's E506 producers are
its list-shape faults (an ERROR element, comma, whitespace or entry in the
list); the only one any authored file reaches is the ERROR element of
example 3. Every utterance in such a file is then by an undeclared speaker
(E522). A header declaring at least one `CODE Role` entry is not reported.

**Trigger**: See examples above

## CHAT Rule

`@Participants` "lists all of the speakers within the file", each as
`XXX Name Role` with the name optional (https://talkbank.org/0info/manuals/CHAT.html#Participants_Header).

## Notes

- An entry with a code but no role is E513; a single word that is neither
  is read as a code without a role, also E513 (E512 is unreachable, see
  its spec).
- The authored separator-spacing control exercises the grammar's optional
  trailing participant whitespace. It must preserve both typed entries;
  no recovery state is fabricated and no new CHECK agreement is claimed.
