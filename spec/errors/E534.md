## Description

An `@Options` header contains a flag that is not one of the recognized option values. The file parses successfully but the unsupported flag is stored as `Unsupported(String)` and flagged during validation.

## Expected Behavior

- **Parser**: Should succeed, syntax is valid
- **Validator**: Should report E534, unsupported @Options value 'badoption'

## CHAT Rule

The `@Options` header accepts the recognized flags `CA` and `NoAlign`.
Other values, including legacy `IPA`, are preserved but reported as unsupported.

Reference: <https://talkbank.org/0info/manuals/CHAT.html#Options_Header>

## Notes

This is an error-level diagnostic. Unsupported option values are preserved in the model as `Unsupported(String)` for roundtrip fidelity but flagged so users can correct them.

The `multi` and `multiple` timing options are also unsupported. The paired
examples in `E305_bullet_retention.md` retain both spellings and observe E534;
their E305 `legal` claims assert only that an utterance terminator is present.
CHECK's internal recognition of `multi` is not authority to admit a new Chatter
option or to reinterpret unsupported values as a supported timing policy.
