**Last updated:** 2026-09-07 23:15 EDT

## Description

A scoped annotation is opened with `[` and never given a body or a closing
`]`, so there is no annotation to attach to the preceding word.

## Expected Behavior

Recovery reports the broken annotation as E375 when the lone `[` ends the
utterance, and as E316 elsewhere. E314 names exactly this shape but cannot
fire at all: its guard is `error_text == "["`, and the E312 guard placed
above it in the same function already claims every text that starts with `[`
and does not end with `]`, which a lone `[` does. E314 is dominated dead code
rather than a rule waiting for the right input.

**Trigger**: See example above

## CHAT Rule

Scoped symbols are square-bracketed codes with a body, closed before the next
word: <https://talkbank.org/0info/manuals/CHAT.html#Scoped_Symbols>.

## Notes

- The subsumption is the current state of recovery, not a ruling that E375 is
  the better verdict; the two codes describe the same defect at different
  grain.
- No CHAT input can demonstrate E314, so the missing example is not the
  defect. There is one construction site, and it is unreachable for every
  possible string: `analyze_error_node` tests `starts with '[' and does not
  end with ']'` (E312) before it tests `== "["` (E314). Closing this is a code
  change, either ordering the exact-`[` test above the E312 guard or deleting
  a branch nothing can reach, plus a registry status that stops claiming the
  check runs.
