# Retained validation fixture (not a generated corpus)

**Status:** Reference
**Last updated:** [Git history](https://github.com/TalkBank/chatter/commits/main/tests/error_corpus/validation_errors/README.md)

This directory once held a hand-written validation-error corpus emitted by the
`generate_error_corpus` binary (`crates/talkbank-parser-tests/src/bin/`). That
generator's validation half was retired once `spec/errors/` became the single
source of truth for validation tests: the spec-driven corpus is generated by
`just spec-gen` into
`crates/talkbank-parser-tests/tests/error_corpus/validation_errors/` (a
crate-relative path, distinct from this repo-root directory) and consumed by the
data-driven runner
[`validation_error_corpus.rs`](../../../crates/talkbank-parser-tests/tests/integration/validation_error_corpus.rs).

`E601_invalid_dependent_tier.cha` is **retained as a committed, hand-maintained
fixture**, not generated by any tool. Its consumers include error-line rendering
and desktop bridge contracts that depend on its content and line layout:

- [`render_parity.rs`](../../../crates/talkbank-transform/tests/integration/render_parity.rs)
  (error line-numbering parity)
- [`validation_bridge.rs`](../../../apps/chatter-desktop/src-tauri/tests/validation_bridge.rs)
  (desktop rendering and CLAN navigation)

`E531_media_filename_mismatch.cha` is also retained as a committed,
hand-maintained fixture: its `@Media: wrong-basename, audio` header
deliberately does not match the fixture's own basename, so any validation
path that runs `check_media_filename_match` (E531 / CLAN CHECK 157) against
it must report the mismatch. `apps/chatter-desktop/src-tauri/tests/validation_bridge.rs`
uses it as a regression guard that the desktop app's single-file validation
path runs this check identically to its directory-validation path and to
`chatter validate`.

`E552_unlinked_with_wor_timing.cha` is likewise retained and hand-maintained:
`@Media ... unlinked` with timing bullets ONLY in the `%wor` tier (no
main-tier bullets).
[`e552_message_quality.rs`](../../../crates/talkbank-transform/tests/integration/e552_message_quality.rs)
drives it through the full pipeline (alignment on) and pins the E552 message
that names the `%wor` tier and offers both remedies; real CLAN CHECK accepts
this file (grounded 2026-07-07), so the case is deliberate chatter-stricter
behavior whose message must self-explain. The pipeline's
[`parse.rs`](../../../crates/talkbank-transform/src/pipeline/parse.rs) also uses
it to verify required-validation rejection with a null diagnostic sink.

Do not delete or regenerate these files. Review all consumers before changing
their bytes; preserve their boundary contracts rather than treating them as
disposable generated fixtures. The consumers above are a navigation aid, not
an exhaustive dependency inventory.
